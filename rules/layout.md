# 디렉터리 배치 규칙

## 현재 존재하는 디렉터리

| 디렉터리 | 용도 |
|---|---|
| `rules/` | 에이전트와 참여자가 지켜야 할 규칙 문서. 주제별로 나누어 둔다 |
| `scripts/` | 훅 설치, 검사처럼 반복 실행하는 셸 스크립트 |
| `docs/` | 설계 문서와 계획 문서처럼 저장소 자체에 대한 참고 자료 |
| `.claude/` | Claude Code 세션의 흐름(세션 시작·종료, 도구 호출 전후)에 걸리는 훅과 스킬과 설정. `.claude/settings.json` 은 저장소에 커밋되어 모든 참여자가 공유한다 |
| `.githooks/` | `git commit` 과 `git push` 명령 자체에 걸리는 git hook. 그 명령을 누가 실행했는지와 무관하므로, Claude Code 로 작업하든 터미널에서 직접 치든 똑같이 적용된다 |

`.claude/` 와 `.githooks/` 의 차이는 누가 쓰는가가 아니라 무엇에 걸리는가다.
`.claude/` 는 Claude Code 세션의 흐름에 걸리고, `.githooks/` 는 `git commit`
과 `git push` 명령 자체에 걸린다.

## 아직 정해지지 않은 것

저장소의 실제 작업 내용, 즉 이 저장소가 최종적으로 무엇을 담을지는 아직
정해지지 않았다. 기존 작업 디렉터리와 요구사항이 전달되면 `/intake` 가
그것을 읽고 어디에 배치할지 정한다.

## 새 파일을 어디에 둘지 판단하는 기준

- 참여자와 에이전트가 지켜야 할 규칙이면 `rules/` 에 둔다. 규칙 하나가
  지나치게 길어지면 주제를 나누어 새 문서를 만든다.
- 반복 실행하는 셸 스크립트면 `scripts/` 에 둔다.
- 저장소의 설계나 배경을 설명하는 문서면 `docs/` 에 둔다.
- Claude Code 가 실행 시점에 참조하는 훅이나 스킬이면 `.claude/` 아래 정해진
  하위 구조를 따른다.
- 위 어디에도 속하지 않고 저장소의 실제 내용에 해당하면, `/intake` 가 정한
  배치를 따른다.

## 저장소에 넣지 않는 것

- 비밀값 (API 키, 토큰, 비밀번호)
- 대용량 이진 파일
- 참여자 개인의 로컬 전용 설정 (예: .claude/settings.local.json)

## 문서 작성 규칙

문서는 마크다운으로 쓰고 한국어로 작성한다.
