# /intake

기존 작업 디렉터리와 요구사항을 받아 저장소를 채운다.

1. 사용자가 알려준 원본 디렉터리를 읽고 파일 목록과 성격을 파악한다.
2. `rules/layout.md` 의 배치 규칙에 따라 각 파일이 어디로 가야 하는지 정하고,
   그 계획을 사용자에게 보여주고 승인받는다. **파일을 옮기기 전에 반드시
   배치 계획을 표로 보여주고 승인받는다. 승인 없이 복사하지 않는다.**
3. 승인된 계획대로 파일을 복사하고, 저장소에 맞지 않는 파일은 제외한 이유와
   함께 보고한다. **원본 디렉터리를 수정하거나 지우지 않는다. 복사만
   한다.**
4. 요구사항을 읽고 CLAUDE.md 의 개요 부분을 채운다.
5. 요구사항에서 도출되는 일감을 GitHub 이슈로 쪼갠다. 각 이슈는 하나의
   `/start` 로 착수할 수 있는 크기여야 한다.
6. 전체 결과를 보고한다.

## 배치 기준

배치 기준은 `rules/layout.md` 를 따른다.

## 비밀값이 들어 있는 파일

비밀값(API 키, 토큰, 비밀번호)이 들어 있을 수 있는 파일은 복사 대상에서
빼고, 어떤 파일을 왜 뺐는지 보고한다.

## 위임

파일을 읽고 분류하는 실무는 `sonnet` 서브에이전트에 맡긴다. 배치 판단과
사용자 확인은 메인 세션이 한다. 근거는 `rules/delegation.md` 다.

## 원격이 없을 때

5단계의 이슈 생성은 원격이 필요하다. 원격이 연결되어 있지 않으면 그 사실을
사용자에게 알리고, 파일 배치와 CLAUDE.md 갱신까지만 수행한 뒤 멈춘다.
