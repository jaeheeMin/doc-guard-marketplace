# /release

1. 마지막 릴리즈 태그 이후 main 에 병합된 커밋과 PR 과 닫힌 이슈를 모은다.
   마지막 태그가 없으면 저장소의 첫 커밋부터 모은다.
2. `rules/issue-and-release.md` 의 형식으로 릴리즈 노트를 작성한다. 변경을
   추가, 수정, 문서, 기타로 분류하고 각 항목에 PR 번호를 붙인다.
3. 버전을 정한다. 기본은 날짜 기반 `YYYY.MM.DD` 이고, 같은 날 두 번째
   릴리즈부터는 뒤에 순번을 붙인다.
4. 노트를 사용자에게 보여주고 승인받은 뒤 GitHub Release 를 발행한다.
   **승인 없이 발행하지 않는다.**

## 노트 형식과 버전 규칙

릴리즈 노트의 절 구성과 버전 형식은 `rules/issue-and-release.md` 를 따른다.

## 원격이 없을 때

PR 목록과 닫힌 이슈 목록은 `gh` 로 원격에서 가져와야 한다. 원격이 연결되어
있지 않으면 그 정보를 모을 수 없으므로, 로컬 커밋 로그만으로 초안을 만들 수
있다는 사실과 함께 안내한다. GitHub Release 발행 자체도 원격이 필요하므로,
원격이 없으면 발행 단계는 수행하지 않고 그 사실을 사용자에게 알리고 멈춘다.
